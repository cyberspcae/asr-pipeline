# 录音 → 文稿：一个分四步的半成品流水线

**输入是一段录音，输出是一份文稿，到此为止。**

这不是一个"一键把录音变成复习笔记"的工具。它只负责把声音变成文字，
中间该有的处理（前处理、切片、调用识别接口）都做，但**每一步是独立的、
看得见、能单独重跑的**，产物全部落盘。

> 输出的那份逐字稿本身就是**半成品**：它可以直接读，也可以作为以后做
> 大纲、纠错、自测卡、检索的输入。要不要往下做、做成什么样，由你决定，
> 本项目不替你决定，也不越界。

## 它不做什么

以下功能**故意没有**，因为那属于"一步到位"：结构化笔记、知识点大纲、
术语纠错、背景人声/可疑段标记、自测卡、Anki 导出、时间戳回听工具。
需要时在项目里再加一个 `05_xxx.py` 读 `04_transcript.md` 就行，前四步不用改。

## 项目结构

```
asr-pipeline/
├── README.md            本文件
├── config.example.json  配置模板（入版本库，密钥留空）
├── config.json           本地配置，可填密钥（已被 .gitignore 忽略）
├── common.py            共用的小工具（配置/日志/命令/时间格式）
├── run.py               ★ 推荐入口：一条命令跑完全程
├── 01_prepare.py        第1步：录音 → 统一音频
├── 02_split.py          第2步：统一音频 → 分段音频 + 分段时间码
├── 03_transcribe.py     第3步：分段音频 → 每段一个 txt
├── 04_merge.py          第4步：每段 txt → 文稿（终点）
├── .gitignore
├── bin/                 放你自己下载的 ffmpeg.exe（见「快速开始」里的链接）
└── workspace/           运行产物，按录音名分目录（已被 git 忽略）
    └── 我的录音/
        ├── 01_prep.wav             前处理后的音频
        ├── 02_segments.json        分段清单（起止时间、文件路径）
        ├── 02_audio/seg_000.wav    每段小音频
        ├── 03_text/seg_000.txt     每段文字
        ├── 04_transcript.md        文稿（带时间码）★ 终点
        └── 04_transcript.txt       文稿（纯文字）  ★ 终点
```

## 四步流程

| 步骤 | 脚本 | 读什么 | 写出什么 | 能不能单独重跑 |
|---|---|---|---|---|
| 1 前处理 | `01_prepare.py` | 原始录音 | `01_prep.wav` | 能（`--redo`） |
| 2 分片 | `02_split.py` | `01_prep.wav` | `02_segments.json` + `02_audio/` | 能（`--redo`） |
| 3 转写 | `03_transcribe.py` | `02_audio/` | `03_text/*.txt` | 能，而且**能只重跑某一段** |
| 4 合并 | `04_merge.py` | `03_text/*.txt` | 两份文稿 | 能，随时重跑 |

每一步只依赖上一步写出的文件，不看别的。所以你可以听一听 `01_prep.wav`、
打开 `02_segments.json` 看看切得对不对、直接改某个 `seg_003.txt`，
然后再往下跑——中间产物不是临时文件，是这个项目的一等公民。

## 快速开始

依赖只有 **Python 3.8+** 和 **ffmpeg**。脚本会优先使用项目 `bin/` 里的
`ffmpeg.exe`，没有再找系统 PATH。Windows 推荐：下载下面的压缩包，把里面
`bin/` 文件夹中的 `ffmpeg.exe` 复制到本项目的 `bin/` 里即可，
不用安装、不用配 PATH：

- <https://www.gyan.dev/ffmpeg/builds/ffmpeg-release-essentials.zip>
- 备选：<https://github.com/BtbN/FFmpeg-Builds/releases/latest/download/ffmpeg-master-latest-win64-lgpl.zip>

没有 pip 包，不用建虚拟环境。配置二选一（代码优先读 `config.json`）：

- 把 `config.example.json` 复制成 `config.json`，在里面填自己的 `"api_key"`；
- 或者不填 key，改设环境变量 `SILICONFLOW_API_KEY`。

`config.json` 已被 `.gitignore` 忽略，填了密钥也不会被提交进仓库。

**方式一 · 一条命令（日常用这个）**

```bash
python run.py 我的录音.MP3
```

处理过程直接显示在命令行窗口里。跑完在 `workspace/我的录音/` 里拿两样东西：

- `01_prep.wav` —— 处理过的音频（前处理后的 16 kHz WAV）
- `04_transcript.txt` —— 文稿（纯文字）；`04_transcript.md` 同内容，每段带 `[mm:ss]` 时间码

`run.py` 只是按顺序执行下面四个分步脚本，中断后再跑一次会自动从断点继续，
已转写的段不会重复扣额度。想全部重来加 `--redo`。

**方式二 · 分四步跑（想检查或重跑中间某一步时用）**

```bash
python 01_prepare.py      我的录音.MP3
python 02_split.py        workspace/我的录音
python 03_transcribe.py   workspace/我的录音
python 04_merge.py        workspace/我的录音
```

> 第 1 步会用录音文件名建任务目录。所以「`我的录音.MP3`」对应
> 「`workspace/我的录音`」。文件名相同会复用同一个目录，换录音请换文件名。

## 每一步在干什么

**第 1 步 · 前处理**
统一成 16 kHz / 单声道 WAV，并做 `highpass=f=100` + `loudnorm=I=-20:TP=-2:LRA=7`。
前者切掉空调、风扇、桌面震动的低频；后者把整体响度提到合适水平且控制峰值不削波。
实测里这是**单项收益最大**的一步：同一段录音，不做前处理错字率 44%，做了降到 21% 左右。

**第 2 步 · 分片**
按 60 秒网格切开，再把切点吸附到附近最近的停顿处（尽量不切断句子）。
为什么不只按静音切：实测中降噪后的录音底噪偏高，静音检测在后半段常常一处
停顿都检不出来，只按静音切会切出上百秒的长段。所以以网格为主、静音点为辅。
每段保留原始起止时间，写进 `02_segments.json`。

**第 3 步 · 转写**
逐段 POST 到识别接口（当前 `XingChenAGI/XingChenASR-V3.2-Ultra`），一段写一个 txt。
请求里会带上 `response_format=json`——Ultra 模型**必须**显式带这个参数，否则接口
直接返回 HTTP 500（上一轮实测踩到过）；若换回不需要它的模型，把 `config.json`
里的 `response_format` 清空即可，代码会自动不发这个字段。
**这个 txt 就是缓存**：已存在就跳过，不重复扣额度；失败不写空文件，下次自动重试。
想换引擎或改提示词，改 `config.json` 后重跑即可。

**第 4 步 · 合并**
按分段顺序拼成一份文稿，同时输出纯文字版和带时间码版。它不判断对不对、
不删任何内容、不"整理"——原样给你。识别结果本来就可能有错字、漏句，
或把旁人说话混进来，所以文稿开头有一行提醒：关键内容请按时间戳回听。

## config.json 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `api_key` | 空（模板） | 在 `config.json` 里填自己的密钥；留空则改用环境变量 `SILICONFLOW_API_KEY` |
| `api_url` | 硅基流动转录接口 | 换平台就改这里 |
| `model` | `XingChenAGI/XingChenASR-V3.2-Ultra` | 模型名；换模型只需改这一行 |
| `response_format` | `json` | 返回格式。Ultra 必须带 `json`，否则 HTTP 500；不需要就清空或删掉这一行 |
| `sample_rate` / `channels` | 16000 / 1 | 输出给 ASR 的音频格式 |
| `preprocess_filter` | `highpass=100,loudnorm=...` | 第 1 步的 ffmpeg 滤镜串 |
| `seg_seconds` | 60 | 分片目标长度（秒） |
| `snap_window_sec` | 12 | 切点向附近停顿吸附的搜索窗口 |
| `silence_db` / `silence_min_dur` | -35 / 0.45 | 静音检测阈值与最短时长 |
| `min_seg_sec` | 18 | 两个切点之间的最小间隔 |
| `api_timeout_sec` / `api_retries` | 200 / 3 | 单次超时与重试次数 |

## 常见操作

| 想做的事 | 怎么做 |
|---|---|
| 只重转某一段 | 删掉 `workspace/我的录音/03_text/seg_003.txt`，重跑第 3 步 |
| 全部重转 | 第 3 步加 `--redo` |
| 改了分片参数 | 第 2 步加 `--redo`，然后**必须重跑第 3、4 步** |
| 换识别模型 | 改 `config.json` 的 `model`，删掉 `03_text/` 重跑第 3、4 步；换回不需要 `response_format` 的模型时，把该项清空 |
| 只想重出文稿 | 直接重跑第 4 步（不花额度） |
| 处理下一节课 | 换个录音文件名，从第 1 步重新跑一遍 |
| 清理某次录音 | 删掉 `workspace/我的录音/` 整个目录 |

## 几轮实测沉淀下来的结论（为什么这么设计）

- **录音端比模型重要**：录音笔设 160kbps、降噪 5 级，尽量靠近老师、
  远离电脑风扇和同学。15 级降噪会削掉字头弱辅音（「踔厉」→「出力」），
  全关则底噪失控；5 级是折中。
- **背景人声是课堂场景的头号难点**：同学私下讨论会被识别成通顺中文混进
  正文，比单纯的错字更难发现。坐第一排做物理隔离，比任何算法都有效。
- **前处理 > 换模型**：响度归一化一项就能挽回约 20 个百分点的错字率。
- **别指望逐字无误**：目前条件下最优仍在 15~20% 错字率。这份文稿适合当
  「课堂索引」——忘了哪个知识点，按时间戳回听那一段，而不是照抄当笔记。

## 注意事项

- **密钥安全**：`config.json` 已被 `.gitignore` 忽略，密钥放这里不会进仓库；
  仓库里的 `config.example.json` 是空模板，**千万别把真实 key 填进模板并提交**。
  如果 key 曾经暴露过，去平台后台作废并重新生成；也可以不填 key，改用环境变量
  `SILICONFLOW_API_KEY`（两者都设时，`config.json` 里的优先）。
- **API 费用**：转写按音频时长计费，是否免费及额度请到平台账单确认。
  第 3 步的跳过机制可以避免重复转写重复扣费。
- **隐私**：课堂录音涉及老师和同学，用之前确认学校规定、最好先跟老师打招呼；
  音频只用于自己复习，不外传，转写完及时清理云端副本。
- **文稿有错**：识别错字、漏句、混入旁人说话都可能发生，关键结论以回听为准。
